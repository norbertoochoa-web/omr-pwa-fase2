## 3. ENDPOINTS DISPONIBLES

| Método | Ruta | Request | Response |
|--------|------|---------|----------|
| POST   | /api/v1/auth/login | { email, password } | { token, user_id, subscription } |
| GET    | /api/v1/subscription/{id} | Bearer token | { status, max_images, expires } |
| POST   | /api/v1/sessions | { name? } | { session_token, status: "OPEN" } |
| GET    | /api/v1/sessions | - | Lista de sesiones del usuario |
| GET    | /api/v1/sessions/{id} | - | Detalle de sesión |
| POST   | /api/v1/upload | multipart: image, session_id | { image_id, status, answers, score, total } |
| POST   | /api/v1/sessions/{id}/finish | - | { status: "COMPLETED", emailed, txt_filename } |
| GET    | /api/v1/sessions/{id}/download | - | Archivo .txt Delphi 7 |
| GET    | /api/v1/health | - | { status: "healthy", version: "2.0.0" } |

## 4. FLUJO MVP

1. LOGIN: app -> { email, password } -> backend valida -> { token, subscription }
2. CREAR SESIÓN: app -> {} -> backend -> { session_token }
3. CAPTURAR + SUBIR: app captura foto -> blob -> POST /upload (multipart)
   Backend: CropOnMarkers (enderezar) -> read_omr_response (leer burbujas)
            -> EvaluationEngine (puntuar) -> guarda en DB
   Response: { answers: { Q1: "A", Q2: "B", ... }, score: 45, total: 60 }
4. FINALIZAR: app -> POST /sessions/{id}/finish
   Backend: genera .txt (Delphi 7), envía email (opcional)
5. DESCARGAR: app -> GET /sessions/{id}/download -> .txt

## 5. COMPATIBILIDAD CON FASE 1

- Login: acepta email (como Fase 1), devuelve subscription object
- Sessions: ID generado por backend (UUID), no SESSION_<timestamp>
  -> Requiere cambio menor en frontend Fase 1 para adaptarse
- Upload: field name = "image" (igual que Fase 1)
- Download: mismo formato .txt Delphi 7
