### Bugs encontrados y corregidos

| # | Problema | Síntoma | Fix |
|---|----------|---------|-----|
| 1 | `createSession` enviaba `{session_id, user_id}` pero backend espera `{name}` | Sesión nunca se creaba en backend | `api.js:69` → enviar `{name}` |
| 2 | Frontend usaba `"SESSION_1747353824093"` en vez del UUID del backend | Upload fallaba con 422 (UUID inválido) | `Camera.js:19-23` → usar `result.session_token` |
| 3 | API URL en `.env` tenía puerto **3001** (mock viejo), backend corre en **8000** | "Network error" en login | `api.js:7` eliminar filtro 'localhost'; `.env` → puerto 8000 |
| 4 | `getBaseUrl()` saltaba env vars que contenían 'localhost' | Fallback a puerto 3001 aunque hubiera env var correcta | api.js: eliminar `!envUrl.includes('localhost')` |
| 5 | Falta de auto-sync tras captura | Imagen quedaba en IndexedDB, nunca llegaba al backend | Upload directo con `fetch` (sin cola) |
| 6 | Fallback "Usar galería" no hacía upload | Imagen se guardaba en DB pero no se procesaba | `handleFallbackCapture` ahora hace upload directo |
| 7 | Botón "Seleccionar imagen" dentro de div `pointer-events-none` | Click no funcionaba | Fallback reemplaza el `flex-1.relative`, no el overlay |
| 8 | Sesión se creaba DESPUÉS de getUserMedia | `currentSessionId=null` si cámara fallaba | Sesión creada antes de cámara |
| 9 | PWA Service Worker cacheaba JS viejo | Usuario nunca recibía las correcciones | `vite.config.js`: runtimeCaching → `NetworkOnly` |
| 10 | Toast desaparecía en 2.5s | Usuario no veía errores | Toast extendido a 3.5s + barra de estado persistente |

### Estado actual del sistema

```
Login → POST /api/v1/auth/login → 200
Sesión → POST /api/v1/sessions {name} → 201, devuelve UUID
Upload → POST /api/v1/upload (multipart) → 200, devuelve {status, answers, score}
Download → GET /api/v1/sessions/{UUID}/download → TXT file
```
